👤 WHAT IS IT?
   A Ruby on Rails platform for mutual fund distribution in India
   Connects: Investors ↔ Distributors/RIAs ↔ AMCs (Fund Companies)

💼 BUSINESS PROBLEM SOLVED
   BEFORE: Manual, paper-based, 5-7 days process
   AFTER: Automated, digital, 15 minutes + 1 day confirmation

🏗️ CORE BUSINESS FLOWS

   1️⃣ ONBOARDING (15 min)
      - Personal details entry
      - Instant KYC verification via external service
      - Email & phone verification (OTP)
      - Bank account addition
      - Ready for investing

   2️⃣ LUMP-SUM INVESTMENT (5-10 min)
      - Select fund & amount
      - Choose payment method (UPI/Card/NetBanking)
      - Payment at gateway
      - Background RTA registration (automatic)
      - Units allocated next day

   3️⃣ RECURRING INVESTMENT - SIP (Set once, automatic monthly)
      - Create SIP (₹5000/month for 5 years)
      - Create mandate (payment authorization)
      - Investor approves mandate
      - SIP activated
      - Every month: Automatic deposit + payment + RTA registration
      - No user interaction needed after setup

🛠️ TECHNOLOGY STACK

   Backend:        Ruby 3.2.8 + Rails 7.0
   Database:       PostgreSQL (persistent data)
   Cache/Queue:    Redis (real-time caching + job queue)
   Background:     Sidekiq + Sidekiq-Cron (async jobs + scheduling)
   Web Server:     Puma
   Container:      Docker
   Admin Panel:    Motor Admin (Rails admin dashboard)
   
   Integrations:
   - Payment: Razorpay, Billdesk, SBI, Cashfree, Camspay, DSP
   - KYC: Signzy, CAMS, Boharr (identity verification)
   - RTA: CAMS, KARVY, DSP (fund registries)
   - SMS/Email: Twilio, Sendgrid, Gupshup

💎 RUBY ON RAILS CONCEPTS USED

   ✓ Models & Active Record (ORM - Object-Relational Mapping)
   ✓ Associations (belongs_to, has_many, has_one)
   ✓ Scopes (reusable filters on data)
   ✓ Validations (ensure data integrity)
   ✓ Callbacks (hooks in object lifecycle)
   ✓ Enums (type-safe status management)
   ✓ Instance & Class Methods (custom logic)
   ✓ Modules/Concerns (code reusability)
   ✓ Blocks & Lambdas (functional programming)
   ✓ Self-referential associations (hierarchies)
   ✓ Optional relationships (nullable foreign keys)
   ✓ Eager loading (performance optimization)

📊 KEY DATABASE MODELS

   Partner
   ├─ Types: AMC, Distributor, RIA
   ├─ Relationships: Partners → Onboardings → Accounts
   └─ Purpose: Distribution partner

   Onboarding
   ├─ Investor registration & KYC verification
   ├─ Tax classification (Individual, HUF, NRI, etc.)
   └─ Purpose: Complete investor profile

   Account (Folio)
   ├─ Represents one investment account with one AMC
   ├─ Holding mode: Joint, Either-or, Single
   └─ Purpose: Fund holding at AMC

   Fund
   ├─ Mutual fund scheme (e.g., SBI Balanced Fund)
   ├─ NAV (Net Asset Value - price per unit)
   └─ Purpose: Investment product definition

   Deposit
   ├─ One-time investment transaction
   ├─ Status flow: created → payment_made → completed
   └─ Purpose: Record of investment

   SIP
   ├─ Systematic Investment Plan (recurring)
   ├─ Linked to mandate for recurring payments
   ├─ Status: created → active → completed
   └─ Purpose: Automated recurring investment

   Mandate
   ├─ Payment authorization for recurring debits
   ├─ Methods: NetBanking, Debit Card, UPI
   ├─ Status: pending → completed → cancelled
   └─ Purpose: Recurring payment authorization

🔄 AUTOMATED WORKFLOWS

   WORKFLOW 1: Deposit Registration
   ┌────────────────────────────────────┐
   │ 1. Investor pays at gateway        │ (Synchronous)
   │ 2. Webhook callback received       │ (Synchronous)
   │ 3. Status updated to payment_made  │ (Synchronous)
   │ 4. RTA job queued in Redis         │ (Synchronous)
   │ 5. Background worker processes     │ (Asynchronous)
   │ 6. Sent to RTA via API/SFTP        │ (Async)
   │ 7. Daily reconciliation processes  │ (Async scheduled)
   │ 8. Partner notified via webhook    │ (Async)
   └────────────────────────────────────┘
   Timeline: 2 min (sync) + 1 day (async reconciliation)

   WORKFLOW 2: SIP Execution (Recurring)
   ┌────────────────────────────────────┐
   │ Every month on SIP day:            │
   │ 1. Sidekiq cron job triggers       │
   │ 2. Check all active SIPs           │
   │ 3. Create deposit automatically    │
   │ 4. Collect payment via mandate     │
   │ 5. Submit to RTA                   │
   │ 6. Reconcile daily                 │
   │ 7. Add units to portfolio          │
   │ 8. No investor interaction         │
   └────────────────────────────────────┘
   Timeline: Fully automated, 0 user action per month

⚙️ BACKGROUND JOBS (SIDEKIQ)

   TriggerSipWorker
   → Runs daily, creates deposits for active SIPs
   → Collects payment automatically
   → Submits to RTA

   RtaSubmissionWorker
   → Sends deposit details to RTA
   → Handles different RTA formats (CAMS, KARVY, DSP)
   → Retries on failure

   ReconciliationWorker
   → Processes RTA mailback files daily
   → Extracts confirmed units
   → Updates deposit records
   → Triggers webhooks

   WebhookWorker
   → Notifies partners of events
   → Guarantees delivery with retries
   → Logs all communications

   Why Async?
   → Don't block investor waiting for response
   → Handle 1000s of operations daily
   → Scale with multiple workers
   → Retry failures automatically

   - Audit trails (every transaction logged)

💡 KEY INSIGHTS

   1. Multi-tenancy: Multiple distributors sharing one platform
      → Isolated data, shared infrastructure
      → API keys + partner validation

   2. Async-first architecture: 
      → Never wait for slow operations
      → Queue jobs, respond immediately
      → Process in background

   3. Integration complexity:
      → Acts as translator between multiple systems
      → Each external service has different format
      → Adapter pattern handles variations

   4. Scale handling:
      → 1000s of daily SIP triggers (1st of month spike)
      → Handled via async queuing + multiple workers
      → Database optimization (indexes, caching)

   5. Fintech constraints:
      → Cannot lose transactions
      → Must reconcile with RTA daily
      → Audit trail for compliance
      → Real-time data accuracy
